# Oatly × ProBar — готовий проєкт для Vercel

Оновлений лендинг на основі `OATLY_ProBar_landing_mockup_v21_safe_client_fixed.html`.
Оригінальний файл та матеріали проєкту не змінено. Публікацію на Vercel ще не виконано.

## Що оновлено

- Фірмовий Oatly у шапці поруч із ProBar, на першому екрані, у блоках переваг, HoReCa, підтримки, заявки, футері та мобільній кнопці. Декоративний водяний знак також використовує логотип.
- Збережено структуру, кольори, відео, акцію та основний текст вихідного макета.
- У промоблоці вказана актуальна ціна: **2 285 грн за ящик**.
- Фото цитрусового напою додане до підтримки й заставки відео; фото звороту пакування відкривається посиланням «Роздивитися пакування».
- Фото оптимізовано у WebP. Усі зображення та відео зберігаються в проєкті. Шрифти Manrope та Oswald завантажуються з Google Fonts; є системні запасні шрифти.
- Замість декоративної форми — справжні поля, перевірка даних, стан надсилання, підтвердження/помилка та серверна функція.

## Деплой через інтерфейс Vercel

1. Розпакуйте архів та завантажте вміст папки `oatly-vercel` в окремий Git-репозиторій.
2. У Vercel виберіть **Add New → Project**, імпортуйте репозиторій.
3. Якщо репозиторій містить саму папку `oatly-vercel`, встановіть її як **Root Directory**. Якщо файли проєкту лежать у корені репозиторію, залиште корінь.
4. **Framework Preset: Other**. Конфігурація `vercel.json` задає **Build Command: npm run build**, **Output Directory: dist**. Node.js — **22.x**.
5. Додайте змінні для заявок, описані нижче, та натисніть **Deploy**.

Альтернатива з терміналу, запущеного в цій папці:

```sh
npx vercel
```

Команда потребує входу у ваш обліковий запис Vercel. Для публікації production-версії після перевірки preview:

```sh
npx vercel --prod
```

## Підключення заявок

Основний спосіб для цього проєкту — **Telegram**. Email та webhook залишені як альтернативи без автоматичного дублювання заявок. Значення додаються в **Vercel → Project → Settings → Environment Variables**, для Preview та Production за потреби. Після зміни змінних запустіть новий деплой. Секрети не додавайте у файли сайту чи Git.

### Основний спосіб — Telegram

У Vercel додайте обидві змінні:

- `TELEGRAM_BOT_TOKEN`: наданий токен бота.
- `TELEGRAM_CHAT_ID`: `-1004305846803`.

Бот має бути адміністратором каналу з правом публікації повідомлень. Кожна заявка надходить як повідомлення з ім’ям, телефоном, джерелом та часом за Києвом. Сайт підтверджує успіх лише після позитивної відповіді Telegram із номером повідомлення. Якщо Telegram відхиляє запит, показується помилка; введені дані залишаються у формі.

Telegram має пріоритет над іншими способами. Якщо заповнена лише одна з двох змінних, надсилання повертає помилку конфігурації. На цей момент токен збережений лише у локальному `.env` з правами доступу `600`. Цей файл **не входить до ZIP, Git та файлів деплою**. Після імпорту проєкту обов’язково додайте секрет у Vercel Environment Variables й виконайте новий деплой.

### Альтернатива A — CRM / Make / n8n

- `LEAD_WEBHOOK_URL`: HTTPS-адреса webhook, який приймає заявку й повертає HTTP 2xx після її приймання.
- `LEAD_WEBHOOK_TOKEN`: необов’язковий токен для заголовка `Authorization: Bearer …`.

Сервер надсилає JSON із полями `name`, `phone`, `source`, `submittedAt`.
Сумісність із конкретною CRM потрібно налаштувати на стороні webhook. Якщо webhook задано, він має пріоритет над email.

### Альтернатива B — email через Resend

- `RESEND_API_KEY`: ключ Resend.
- `LEAD_EMAIL_TO`: одна email-адреса одержувача заявок.
- `LEAD_EMAIL_FROM`: адреса відправника на підтвердженому в Resend домені.

Поки жоден спосіб не налаштований, сервер повертає помилку, а сайт пропонує зателефонувати. Заявки не зберігаються локально й не імітують успішне надсилання. Після налаштування перевірте одну реальну заявку й її надходження одержувачу. Реальні email-листи під час підготовки не надсилалися; Telegram перевіряється окремою тестовою заявкою.

## Локальний перегляд і перевірка

Потрібен Node.js 22. Залежності для роботи сайту не потрібні.

```sh
npm run dev
```

Відкрити `http://127.0.0.1:4173`. Для локальної перевірки з реквізитами можна створити `.env` на основі `.env.example` і запустити:

```sh
node --env-file=.env scripts/dev.mjs
```

```sh
npm test
npm run build
```

`npm test` перевіряє валідацію, відмови сервісу надсилання, відсутність конфігурації, Telegram, webhook та email із підміною зовнішніх запитів. Збірка перевіряє наявність локальних ресурсів і створює `dist`.

## Структура

- `public/index.html` — вміст лендингу.
- `public/styles.css` — дизайн і адаптація.
- `public/app.js` — відео та форма.
- `public/assets/` — логотипи, фото, відео.
- `api/lead.js` — серверна функція Vercel для заявок.
- `vercel.json` — конфігурація деплою.
- `.env.example` — порожній шаблон налаштувань.

Номер `0 800 60 60 60`, умови акції `1+1=3`, ціна `2 285 грн за ящик` та робочий час збережені в `public/index.html`.
